# Audit — ehsanrahman.com (follow-up, 2026-09-10)

Scope: the current working tree's `index.html` (including the uncommitted portrait-layout change),
`support.js`, `articles/boeing-737-max/index.html`, `.cpanel.yml`, and `README.md`, plus a small set
of live response-header checks against `ehsanrahman.com`. The vendored React files were checked for
presence and loading, not source-audited. The article's historical claims and third-party source URLs
were not fact-checked in this pass.

This is a findings report only; no production fixes were made as part of the audit.

## Executive status

**No P0 availability defect was found.** The landing page and article render at desktop, mobile, and
portrait-monitor sizes without horizontal overflow. Internal fragment links resolve, IDs are unique,
the article is usable without JavaScript, local React loads normally, and the landing page falls back
to visible text when both local React and the CDN fallback are blocked. The earlier off-screen animation
fix is effective: instrumented canvas drawing dropped from roughly 540 `fillRect` calls per second while
the hero was visible to zero after it left the viewport.

The main current risks are transport configuration and accessibility. Plain HTTP is still served, the
landing glossary is not keyboard-operable, reduced-motion users still receive almost all animation, and
some meaningful small text does not meet WCAG AA contrast. There is also persistent runtime/deployment
debt and a reproducible three-error console baseline on every landing-page load.

## Top 5 (ranked)

1. **HTTPS is not enforced on the live custom domain.** On 2026-09-10,
   `http://ehsanrahman.com/` returned `200 OK` instead of redirecting to HTTPS. The HTTPS response also
   omitted `Strict-Transport-Security`, `Content-Security-Policy`, `X-Content-Type-Options`, and
   `Referrer-Policy`. This permits plaintext delivery and creates a duplicate HTTP origin despite the
   HTTPS canonical URL. `.cpanel.yml:7` does not deploy an `.htaccess`, so this is not currently managed
   by the repository.
2. **The landing glossary fails its keyboard path.** The seven terms at `index.html:250,364-365` are
   focusable spans with `outline:none`, `onClick`, and mouse hover handlers, but no `onFocus`, keyboard
   activation handler, role, accessible expanded state, or tooltip relationship. Tabbing to a term gives
   no visible focus and does not open its definition; Enter/Space do not activate a generic span. The
   root document also lacks `lang="en"` (`index.html:2`). The article's MCAS glossary is substantially
   better: it supplies focus behavior, a tooltip role, and `aria-describedby`.
3. **`prefers-reduced-motion` does not materially reduce the landing animation.** The media query is
   read at `index.html:1448-1453`, but it only parks the radar sweep angle. Aircraft, weather, pulses,
   graph traffic, CSS blink/pulse/fade animations, the requestAnimationFrame loop, and the 800 ms state
   updates continue. Under emulated reduced motion the page still had eight CSS-animated elements and
   the same measured canvas draw activity (about 540 instrumented `fillRect` calls/second) as normal.
4. **Muted small text is below AA contrast.** `#52655d` is approximately 3.18:1 against `#080b0a`
   (and about 2.95:1 over the lighter panel background), below the 4.5:1 requirement for normal text.
   It is used for meaningful 9.5–11 px content and links, including `.aci-wiki`, case years, source notes,
   footer text, and header metadata (`index.html:79,162,165,214,343,1253` and
   `articles/boeing-737-max/index.html:51,86-87`). `#71867e` is about 5.09:1 against the page background and is an existing
   palette-safe replacement where the text is not purely decorative.
5. **Every landing-page load begins with three console errors.** The raw SVG sparkline attributes at
   `index.html:303,317,331` contain `points="{{ sparkKnown }}"`, `{{ sparkKU }}`, and `{{ sparkUU }}`.
   Chrome validates those strings while parsing the hidden source template and reports “Expected
   number” three times before the runtime replaces them with valid coordinates. The sparklines render
   after boot, but a permanently noisy console makes real regressions easier to miss and prevents a
   clean smoke-test baseline.

## Checklist (execute top-down)

### P0 — availability / data loss

- No P0 issue found in this pass.

### P1 — transport & accessibility

- [ ] Force `http://` to `https://` with a permanent redirect at LiteSpeed/cPanel. Once the redirect is
      verified, add HSTS with an initially conservative `max-age`; only add `includeSubDomains` after
      confirming every subdomain supports HTTPS. If this is implemented through `.htaccess`, explicitly
      add that file to `.cpanel.yml`'s publish list.
- [ ] Add low-risk response headers at the host: `X-Content-Type-Options: nosniff` and a deliberate
      `Referrer-Policy` first. Treat CSP as a P2 architecture task because the current landing runtime
      requires inline scripts/styles and `new Function`.
- [ ] Add `lang="en"` to the landing page's `<html>` element (`index.html:2`).
- [ ] Rebuild the landing glossary triggers as native inline buttons, or fully implement the equivalent
      semantics: visible `:focus-visible`, focus-to-open, Enter/Space activation, Escape dismissal,
      `aria-describedby` pointing to a `role="tooltip"`, and an accurate open state. Retest mouse, keyboard,
      touch, and screen-reader output.
- [ ] Honor reduced motion across the whole hero: disable the CSS blink/pulse/fade animations and render
      the canvases as a static snapshot (or update very infrequently) rather than continuing the 60 fps
      loop. The state/sparkline timer should also stop or slow when reduction is requested.
- [ ] Raise meaningful `#52655d` text and link instances to at least 4.5:1 contrast. Keep dimmer colors
      only for genuinely decorative marks; verify hover, visited, and focus states as well as the default.

### P2 — runtime, performance & release integrity

- [ ] Eliminate the three invalid-SVG parser errors without losing dynamic sparkline values. Encode or
      defer the `points` bindings so the browser never parses the raw moustache expressions as SVG data,
      then make “no unexpected console warnings/errors” part of the smoke test.
- [ ] Recover and commit the `dc-runtime` source, or replace the custom runtime with a reproducible build.
      `support.js` now honestly identifies itself as hand-maintained, but fixes still land directly in a
      generated artifact. Its landing boot uses `new Function` (`support.js:688-696`), which requires
      CSP `unsafe-eval` and prevents a strong script policy.
- [ ] Remove the `fetch(location.href)` template self-fetch (`support.js:156-160`) by preserving
      case-sensitive React/SVG attributes during build. Browser caching avoided a second transfer in this
      audit, but the extra fetch/cache lookup, parse, template compilation, and update remain load-bearing
      work and can become a second transfer under different cache headers.
- [ ] Reduce the landing render surface. The rendered root currently contains about 1,496 elements, and
      the 800 ms clock/sparkline tick re-renders and diffs that whole template while the hero is visible.
      Isolate the live dashboard from the 32 closed incident records, or render/update the dynamic widgets
      independently. The existing IntersectionObserver gate should remain; it correctly stops work when
      the hero is off-screen.
- [ ] Make deployment convergent. `.cpanel.yml:7` uses `cp -R`, so files removed from `articles/`,
      `images/`, or `vendor/` can remain publicly reachable forever. Publish a manifest/staging directory
      and synchronize only the owned production paths with deletion, without deleting unrelated files in
      `public_html`. The earlier docs cleanup is working: the audited live docs URL returned 404.
- [ ] Add a small automated smoke suite. At minimum cover normal boot, local-vendor failure plus blocked
      CDN fallback, zero console errors, internal anchors/accordion deep links, glossary keyboard/touch
      behavior, reduced motion, and overflow at 390×844, 1080×1920, and 1440×900.

### P3 — discoverability, semantics & maintenance

- [ ] Fix the article favicon's decoded SVG namespace (`articles/boeing-737-max/index.html:9`): it says
      `http://wws.org/2000/svg`, not `http://www.w3.org/2000/svg`. Prefer one shared favicon asset so the
      two embedded copies cannot drift.
- [ ] Add a dedicated social card and `og:image` metadata to the landing page and article. Both currently
      use `twitter:card=summary` without an image; this was an intentional deferral in the previous audit,
      but it still weakens link previews.
- [ ] Improve landmarks on the landing page: mark the top link group as a labelled `<nav>` and include
      the hero in the primary page structure. In the article, make “PRIMARY RECORD · SOURCES” an actual
      heading so it appears in heading navigation.
- [ ] Improve the no-React fallback. It is now readable rather than blank (about 5,809 visible characters
      in the blocked-dependency test), but it exposes `{{ clock }}` and other moustache values and leaves
      custom loop markup in the DOM. A small static fallback or `<noscript>` presentation would look
      intentional.
- [ ] Refresh `README.md`: it calls the site single-page, omits `articles/`, points to GitHub Pages while
      canonical/deployment use the custom domain, says React normally loads from unpkg even though it is
      vendored, and incorrectly says the site requires network access to boot. Direct `file://` loading
      succeeded in the audit with initialized sparklines and clock.
- [ ] Escape the `&` characters as `&amp;` in both Google Fonts stylesheet URLs to keep the HTML source
      validator-clean, even though browsers currently recover correctly.

## Verification evidence

- Headless Chrome 152, normal boot: landing and article rendered at 1440×900 and 390×844; landing also
  rendered at 1080×1920 with the compact portrait grid. No tested viewport had horizontal overflow.
- Rendered DOM: no duplicate IDs or broken same-page fragment targets; one `<h1>` on each page; decorative
  canvases retain `aria-hidden="true"`.
- Console: article clean; landing reproducibly emitted only the three initial SVG `points` errors during
  normal boot.
- Off-screen performance: approximately 549 instrumented canvas `fillRect` calls/second while visible,
  then zero after scrolling beyond the hero.
- Reduced motion: approximately 540 instrumented canvas `fillRect` calls/second and eight CSS-animated
  elements, confirming that the preference does not reduce overall activity.
- Dependency failure: with local React and both unpkg React URLs blocked, the hide style was removed,
  `x-dc` became visible, and the page exposed readable content rather than remaining blank.
- Live HTTPS: root and article returned 200 and gzip encoding; sampled JS and image assets returned a
  seven-day public cache policy. Live HTTP returned 200 rather than redirecting. The archived docs URL
  returned 404 as intended.
